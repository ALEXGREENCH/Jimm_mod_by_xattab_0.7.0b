# Процесс и ограничения восстановления

Эталон текущей сборки — `preservation/originals/Jimm_MIDP2_RU/Jimm.jar` из пользовательского архива. SHA-256 закреплён. История репозитория 0.6.0a сохранена, исходная точка — `b437e97`.

## Обратимое преобразование имён

ProGuard использовал default package, одинаковые имена полей разных типов и методы, различающиеся только возвращаемым типом. JVM допускает такие определения, Java-исходник — не все. Java-код в `jimm.Jimm` также не может обращаться к классам default package.

`Remap.java` переносит вспомогательные классы в `recovered.C_<release name>`, добавляет типовые суффиксы полям/методам и различает приватные методы владельцем. Хеш в имени — Java String.hashCode дескриптора, а не оценка достоверности. Инструкции не подменяются. После компиляции обратное преобразование возвращает имена релиза.

Основной декомпилятор — Vineflower 1.11.1. CFR 0.152 использовался для вспомогательного чтения спорных фрагментов. Повторяемый вывод декомпилятора доступен через `python tools/recover.py decompile`.

## Исправления исходников

Полный diff: `tools/recovery/midp2-source-repairs.patch`.

- Разделены несовместимые переменные, которым оптимизатор назначил один слот: boolean/int, номер протокола/длина пакета, String/String[], Object/ContactItem.
- Восстановлены приведения примитивных массивов и явные вызовы `intValue()`, `booleanValue()`, `longValue()` для Java 1.3.
- Удалены невозможные присваивания `this`; сохранена реальная ссылка получателя там, где она могла отличаться.
- В SOCKS-пакете разделены версия протокола и длина буфера по оригинальным `iload`/`istore`; сохранены проверки версии и значение первого байта.
- Восстановлены объявления checked exceptions. `InferExceptions.java` — вспомогательный анализ. Общий `Throwable` при повторном выбросе из finally не трактуется как новая декларация. Результат проверен компилятором.
- Удалён избыточный catch/rethrow Throwable вокруг закрытия сокета, не принимаемый Java 1.3. Обработка Exception сохранена.
- Переопределению метода TextList предоставлен public-доступ для принятия Java-компилятором исходного JVM-контракта.

## Проверка

`BytecodeDump.java` сохраняет реальные инструкции, позиции переходов, символические ссылки и обработчики исключений. Сравнивается **исходный JAR с конечным preverified JAR** после возврата имён релиза.

Полного byte-for-byte совпадения нет. Отчёт намеренно показывает расхождения: ECJ вместо неизвестной точной версии исторического javac, другой порядок локальных переменных, StringBuffer lowering, компоновка условий и обработчиков. Возможные ошибки декомпиляции тоже входят в непроверенные расхождения.

Дифференциальные тесты используют два изолированных class loader: эталонный remapped JAR и **скомпилированные исходники**. В библиотечном каталоге только закреплённые зависимости; недостающий класс нельзя взять из оригинального JAR. Сравниваются результаты, типы исключений и изменённые byte[]. Это не заменяет тестирование UI и протокола целиком.

## Сборки и языки

Wayback сохранил файлы под датами 24 сентября 2010 года. Дата snapshot — дата архивирования, не доказательство даты компиляции. Манифесты основных файлов показывают 0.7.0b; light-варианты — 0.5.2b. URL, размеры и SHA-256 записаны в журнале происхождения.

Нельзя переносить `.lng` между произвольными JAR: короткие ключи зависят от конкретной сборки. JSON-словари содержат точные пары из соответствующего бинарника. Унаследованные `.lang` от 0.6 не выдаются за словари 0.7.
